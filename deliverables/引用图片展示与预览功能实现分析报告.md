# 「回答引用图片时展示图片并可预览全图」功能实现分析报告

> 分析对象：kb-deskpet 桌宠 panel 的问答界面（截图即 panel 窗口，非 WeKnora 网页）
> 分析日期：2026-11-13 ｜ 线上版本：WeKnora v0.9.0（与 GitHub Tencent/WeKnora main 一致）
> 结论：**后端零改动即可实现**。引用数据里已经带了图片地址，缺的只是桌宠前端「解析 → 取图 → 渲染 → 预览」这四步。

---

## 一、现状

### 1.1 桌宠 panel 现在怎么渲染引用

截图红框里那排 `[1] 20261112095055.jpg` chip 由 `tauri-app/src/public/js/panel.js` 的 `renderRefs()`（L1009）生成：

- chip 只显示 `[序号] knowledge_title`（图片类知识标题就是文件名）；
- 点击 chip 展开 `ref-body`，内容是 `mdToHtml(r.content.slice(0, 1200))`——图片类 chunk 的 content 是 caption/OCR 文本，**从头到尾看不到图**；
- 引用数据有两个入口，都汇聚到 `renderRefs`：
  - 流式回答：SSE 事件 `response_type === 'references'` → `renderRefs(s, ev.knowledge_references)`（L1963）；
  - 历史消息：`r.references`（L1120）。

### 1.2 WeKnora 官方 Web 前端同样没有图片

官方前端（v0.9.0 源码）里引用交互有三层，全部只出文字：

| 层 | 文件 | 现状 |
|---|---|---|
| 行内引用 chip | `utils/citationMarkdown.ts` | `<kb chunk_id doc/>` → 文字 pill，截断 13 字符 |
| hover 弹窗 | `ChatCitationFloat.vue` | 纯文本摘录（还专门把 markdown 图片语法剥掉） |
| 引用抽屉 | `ChatReferencesDrawer.vue` | 文件图标 + 标题 + 文本 snippet，无缩略图 |

但官方知识库「图片画廊」（`views/knowledge/gallery/`）已经有一整套**取图、缩略图、灯箱预览（缩放/平移/旋转）**的成熟实现，可以直接抄。

## 二、关键发现：数据链路已经就绪（生产环境已验证）

### 2.1 引用 payload 已含图片地址

WeKnora 的引用结构是 `types.SearchResult`（`internal/types/search.go:159`），序列化进消息的 `knowledge_references` 字段，其中：

```go
ChunkType  string  `json:"chunk_type"`       // image_caption / image_ocr / image_vector / summary / text ...
ImageInfo  string  `json:"image_info"`       // JSON 数组字符串：[{"sha256":..., "url":"resource://xxx", "original_url":..., "caption":..., "ocr_text":...}]
MatchedImages []MatchedImage `json:"matched_images,omitempty"`  // [{chunk_id, knowledge_base_id, url}]
```

**生产库实测**（192.168.1.234 WeKnora-postgres，截图那场对话所在的最近消息）：

```
chunk_type=image_caption | kb=9efc0043-... | img=[{"sha256":"b3d92ff1...","url":"resource://4Hn3yxvEUKiMljJB33HZmg",...
chunk_type=image_ocr     | kb=9efc0043-... | img=[{"sha256":"b3d92ff1...","url":"resource://4Hn3yxvEUKiMljJB33HZmg",...
chunk_type=summary       | kb=9efc0043-... | img=(空)
```

两个重要事实：

1. `image_caption` 和 `image_ocr` 是同一张图的两种子 chunk，**共享同一个 `resource://` 句柄**（sha256 相同）→ 前端按 url 去重即可得到「每张图一条」。
2. SSE `references` 事件和历史消息走的都是这份 JSON（`helpers.go: searchResultFromMap` 显式保留 `image_info`，Redis 重放、落库、回放历史全链路不丢字段），所以**历史会话里的旧引用也能直接显示图**。

### 2.2 图片怎么取回：KB 文件代理

`resource://` 是存储句柄，浏览器不能直接当 src。WeKnora 提供受鉴权的文件代理：

```
GET /api/v1/knowledge-bases/:kb_id/files?file_path=resource://4Hn3yxvEUKiMljJB33HZmg
Headers: Authorization: Bearer <token>
         X-Tenant-ID: <登录身份租户>        ← 跨租户共享库必须带
```

- 路由注册：`internal/router/files.go:336`（`serveKBScopedFiles`），守卫是 `Viewer() + KBAccessRead`，内部经 `access.ResolveKBFile` 校验「该资源确实属于这个 KB 的 chunk/文档绑定」后按属主租户取文件——**对 9 个只读共享库同样放行**（与官方 Web 前端展示共享库图片走的是同一条路）。
- 备选 `/files?file_path=`（租户级代理）不适合跨租户共享库场景，不用它。

### 2.3 桌宠侧现成设施

- `tauri-bridge.js` 已有 `kbHeaders()`（L196）：自动带 `Authorization + X-Tenant-ID`（登录身份租户，即 v0.8.19 403 修复定下的规则），取图请求直接复用；
- CSP 为 null（`tauri.conf.json`），`blob:` URL 没有障碍；
- md.js 只放行 http/https 链接——不影响本方案（图片走 DOM API + blob，不进 markdown 管道）。

## 三、实现方案（推荐：只改桌宠前端，约 3 个文件）

### 3.1 数据层：bridge 增加一个 `fetchRefImage`

`tauri-bridge.js` 暴露：

```js
fetchRefImage: async ({ kbId, filePath }) => {
  const cfg = loadCfg();
  const base = normalizeBase();
  const url = `${base}/knowledge-bases/${encodeURIComponent(kbId)}/files?file_path=${encodeURIComponent(filePath)}`;
  const r = await fetch(url, { headers: kbHeaders(cfg.token) });   // 复用现有身份租户头
  if (!r.ok) throw new Error(`image ${r.status}`);
  const blob = await r.blob();
  return { ok: true, objectUrl: URL.createObjectURL(blob) };
}
```

配一个模块级 `Map<resourceUrl, objectUrl>` 缓存 + in-flight 去重（照抄官方 `ImageGallery.vue` L114-165 的成熟写法：同图 chip 和预览共享一个 blob，卸载时 revoke）。

### 3.2 渲染层：`renderRefs` / `toggleRefBody` 改造（panel.js）

```
renderRefs(s, refs):
  1. 解析每个 ref：
     - chunk_type ∈ {image_caption, image_ocr, image_vector} 且 image_info 非空 → 图片段
     - JSON.parse(image_info)[0].url 为 resource:// 句柄；caption/ocr_text 为提示文案
     - 同 url 去重（caption+ocr 双份合一）；summary/text 类保持现状
  2. chip 渲染：
     - 图片段 chip：内嵌 48px 高缩略图 <img>（懒加载：IntersectionObserver 或进入视口才 fetch blob）
       失败兜底退回现在的文件名文字 chip
     - 文字类 chip：完全不变
  3. 排列：图片段 chip 与文字 chip 同排混排（红框那排样式不变，只是部分 chip 变成「缩略图+文件名」）
```

`toggleRefBody` 展开时：图片段的 ref-body 直接渲染大图（宽度撑满气泡，圆角），caption 作为图注文字，不再截 1200 字符。

### 3.3 预览层：panel 内置轻量灯箱

panel.html 加一个复用的全屏遮罩层（panel 本身就是 780px 窗口，遮罩盖住窗口即可）：

- 点击缩略图 / ref-body 大图 → 灯箱打开，显示原图 blob；
- 支持：滚轮缩放（0.2x–5x）、拖拽平移、双击复原、ESC/点击遮罩关闭、多图时 ←/→ 切换（顺序 = refs 去重后的顺序）；
- 不引第三方库，纯 DOM 实现，150 行以内；样式对齐现有 `.ref-body` 的圆角/深浅色变量。

> 可选增强：官方 `GalleryViewer.vue` 的缩放/平移实现可直接移植（`MIN_SCALE=0.2`、以舞台中心为锚点的平移模型），想要体验对齐 Web 端就抄它。

### 3.4 改动清单

| 文件 | 改动 | 量级 |
|---|---|---|
| `tauri-app/src/public/js/tauri-bridge.js` | 新增 `fetchRefImage` + blob 缓存 | ~50 行 |
| `tauri-app/src/public/js/panel.js` | `renderRefs` 解析 image_info、图片段 chip、ref-body 大图 | ~80 行 |

## 四、可选：WeKnora 官方 Web 前端同步改造

如果希望线上 Web（9527）也有同样体验，改动点是三个渲染层文件，数据同样现成：

1. `citationMarkdown.ts::preprocessCitationTags`：`<kb/>` chip 渲染时查 refs 中对应 chunk 的 `image_info`，图片类 chip 输出 `<img class="citation-thumb">`（URL 经 `galleryImageRequest(rawUrl, kbId)` 走代理，渲染用 blob）；
2. `ChatCitationFloat.vue`：popover 顶部加缩略图；
3. `ChatReferencesDrawer.vue`：document 类引用当 `image_info` 非空时渲染缩略图，点击复用 `GalleryViewer.vue` 灯箱（它已支持缩放/平移/旋转/多图切换，props 传 `items/thumbUrls/resolveSrc` 即可）。

注意：官方前端 `CitationKnowledgeRef` TS 类型目前没声明 `image_info`/`knowledge_base_id` 字段（数据在、类型没写），需要补类型声明。

## 五、安全与边界

- **不放宽 md.js**：图片不进 markdown 管道，走 `document.createElement('img')` + blob URL，避免任何 HTML 注入面；
- **鉴权**：blob 请求复用 `kbHeaders()`（身份租户头），跨租户共享库 403 问题已被 v0.8.19 的租户规则覆盖；**不要**退回 `cfg.tenantId`（老版本污染坑）；
- **失败静默降级**：任一图 404/403/超时 → chip 退回文字样式，不影响答案本身；
- **性能**：`resource://` 代理无服务端缩略图，原图直出（手机拍照可能几 MB）。缩略图必须懒加载 + blob 缓存；单条答案引用去重后一般 ≤ 10 张，可接受。若后续图多，可在 kb-embed 容器旁加缩略图生成（属 P2）；
- **内存**：blob URL 在会话切换/窗口关闭时统一 revoke，防泄漏（照抄 ImageGallery 的 releaseBlobs 模式）。

## 六、验收清单

1. 向图片库提问 → 引用区出现「缩略图 + 文件名」chip，summary/文字类引用仍为文字 chip；
2. 点 chip → ref-body 显示大图 + 图注（caption），文字类引用行为不变；
3. 点缩略图/大图 → 灯箱全图预览，滚轮缩放、拖动、ESC 关闭、多图切换正常；
4. 历史会话（含改造前产生的图片引用消息）打开后同样出图；
5. 跨租户共享库（只读共享）中的图片能出图，无 403；断网/图失效时 chip 静默退回文字；
6. 两窗口（panel/pet）事件同步不回归；`npm run check` + `cargo test` 通过后打 tag 发版。

## 七、风险

| 风险 | 说明 | 对策 |
|---|---|---|
| image_info 为空的旧数据 | 早期图片 chunk 可能没有 image_info | 判空走文字 chip，天然兼容 |
| 跨租户 403 | 共享库图片按属主租户解析 | 已由 kbHeaders 身份租户规则覆盖；如仍 403 属 KBAccessRead 权限问题，与后端排查 |
| 大图拖慢渲染 | 无服务端缩略图 | 懒加载 + 缓存；后续可上缩略图服务 |
| refs 超过 6 条被截断 | `renderRefs` 现有 `slice(0, 6)` | 图片类优先展示或调大上限（产品决策） |
