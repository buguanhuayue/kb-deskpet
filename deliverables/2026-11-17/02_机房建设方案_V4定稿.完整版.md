**容量**：192TB 裸 / 两副本 96TB / 可用约 77TB；现有数据 <1TB，够 5–8 年。

> **存储为什么必须独立一对交换机**（不能与业务共用）：副本同步写放大 2–3 倍，与业务共用会被挤占 → 心跳超时 → 误判失联 → 重建雪崩；业务核心升级重启也不打断存储；约 2.7 万 +120 W +2U，省不得。
> **业务核心 2 台堆叠（B 案，已定）**：不为端口，为消除整机单点 + 服务器双上行；约 +1.3 万 / +80 W / +1U。回退 A 案（1 台）：私有云 8 台 / 2,440 W，代价是坏交换机 = 业务区中断 1–2 小时。
> **业务核心必须选三层机型**（S6520X-30QC-EI / S5560X-30C-EI 同级）：贵约 1 万，但省掉一台独立业务核心（3 万 + 2U + 100 W），净省。

## 5 网络改造与配置

> 现状核心实测（`_probe/net_Core_10.220.100.1.txt`）：S6520X-30QC-EI，24×10G + 2×40G，仅用 1/0/1-5、1/0/23、1/0/24，**1/0/6–22 共 17 个万兆口 + 2 个 40G 口全空闲 ⇒ 核心不用换、不用加板卡**；本轮占用 1/0/21、1/0/22 后仍余 15 个万兆口。

### 5.0 设计结论（七条）

| # | 结论 | 依据 |
|---|---|---|
| 1 | **全网三套环境**：集团办公 / 私有云业务（含原研发平台业务）/ 监控专网 | 现状就是三套互不相通；⚠️ 研发平台与监控**撞用 192.168.1.0/24**，本次一并消除 |
| 2 | **出口归属锁死**：移动专线 + 光端机 = 私有云/研发专用；光猫 ×3 + iKuai = 集团办公专用；两条链没有任何一段共用 | 专线静态 IP 111.53.208.218 用于对外发布 443 与固定源 IP 出向；集团宽带 PPPoE 动态地址、NAT 在 iKuai。两条运营商线路必须分开（443 发布不能走动态 IP），但**安全边界统一**：两条链都过同一台防火墙的独立端口/zone |
| 3 | **全网统一边界：办公上网也过防火墙**（核心 1/0/24 + 1/0/22 → FW GE1/0/3 → GE1/0/7 → 上网行为串接 → iKuai） | 全机房安全一张网统一管；NAT 仍在 iKuai、拨号不变；防火墙 HA ×2 兜单点（办公侧双口接线见 5.2 注）；回退走预配脚本（5.10），不再"拔回直连" |
| 4 | **办公与业务物理分离**：两台核心，彼此不直连 | 办公网是最大风险源（终端多、ARP/广播风暴）；分开后办公环路不波及业务 |
| 5 | **防火墙 = 全网唯一边界安全点 + 唯一跨域点**，7 口全部分配（6 口在用 + GE1/0/4 预留 DMZ，**无空闲口**）：GE1/0/1 跨域、1/0/2 业务核心、1/0/3 办公上网·入（对核心 1/0/24）、1/0/4 DMZ 预留、1/0/5 WAN1 专线、1/0/6 WAN2 研发宽带、1/0/7 办公上网·出（→行为管理→iKuai） | 办公出网进 1/0/3、出 1/0/7，**入/出分两个域**（见 5.8⑦）；选型按**开启全部安全功能后实测吞吐 ≥ 2×办公峰值**（厂商实测报告）；**HA 接线**：办公核心 1/0/24→FW-A 0/3、1/0/22→FW-B 0/3，iKuai 双 LAN 口分别接两台 0/7（单口则经 2 口小交换机对接，7.2 待确认）；后续加专线需加网络板卡 |
| 6 | **研发部按网段管理，不按 IP 白名单**：测试 192.168.10.0/24、预发 12.0/24、演示 14.0/24，与生产 2.0/23 二层+三层双隔离 | 十几人并发开虚机是常态；按人写 ACL 半年必乱 |
| 7 | **4 台 Dell 并入私有云**：先直连业务核心原样搬，虚机化后转计算/备用节点，不入存储池 | R730 与新超融合盘型/CPU 代差大，混入存储池拖垮全池；老环境保留回退窗口，不影响现有业务 |

**出口链路（四条链，各为其主）**：

```
链 A · 移动专线（111.53.208.218）——【私有云 / 研发业务专用】
  运营商光纤 → 光端机 FYLO6650-B1（保留，透明二层，8W）
    → 防火墙 GE1/0/5 WAN1（静态 IP 配在此；锐捷退役）
  ★ 光端机直插 WAN1 不过上网行为管理：业务流量无"上网行为"可审计，且不给生产入口加单点

  ★ 全链过安全设备：策略在防火墙（入/出分域）、行为审计在上网行为、NAT 在 iKuai；回退=启用 iKuai 预配备用口 + 核心恢复默认路由（脚本化清单，见 5.10）
链 C · 监控 ——【监控专网，链路不动；仅监控接入交换机迁 R3】
  Nokia 光猫 → 自用 iKuai ×2 → 监控接入交换机 → 海康 ×2 + 大华 NVR
``````

> ① `ip route-static 10.220.20.0 255.255.255.0 192.168.251.1`（研发段回程 → 跨域线）；
> ② `ip route-static 10.220.0.0 255.255.0.0 192.168.253.4`（**办公网全部段**回程 → 上网链核心 SVI；办公核心下挂 VLAN 10/20/100/110/1004 都在 10.220/16 内，只写 /22 会让 VLAN 20/100/110 的回包丢给 WAN 出公网）；
> ③ EDR 例外会话（源 10.220.0.0/22 → 目的 192.168.7.0/24）单独做策略路由，下一跳 192.168.251.1，否则它的回包会被 ② 送到上网链、非对称被丢；
> ④ iKuai 加 `10.220.0.0/16 → 192.168.254.3`（FW HA 虚地址，iKuai 已不与核心同段，回程必须经 FW）。
> **6 条路由缺一不可**：5.0、7.0 漏了，ACL 放行也到不了——包被默认路由丢给 iKuai 出公网（现象：云平台网页打不开、堡垒机连不上）。路由是"路"，ACL 是"门"。
> **不写 192.168.4.0 路由**：存储段故意不通，查不到路径比 ACL 更可靠。permit 必须全在 deny 之前，`rule 20 deny ip` 漏写等于没拦。
> ACL 源地址 **10.220.20.0/24 已定稿**：现网核心预建的 VLAN 1000（网关已配未启用）启用作研发无线段，研发连专用 SSID 自动落段，占位转正、无需再改。

### 5.12 业务上线：新增一个服务怎么让外网访问

**一句话：一个公网 IP、只开 443、靠域名区分业务，不给每个业务分端口。**

| 步 | 做什么 | 谁做 | 耗时 |
|---|---|---|---|
| ① | 虚机/容器起服务，拿内网地址 192.168.2.x:8080 | 研发 | — |
| ② | 入口加一条：`shop.xinyeonline.com.cn` → 192.168.2.55:8080 | 运维 | 1 分钟，apply 即生效 |
| ③ | 阿里云 DNS 加 A 记录 `shop` → 111.53.208.218 | 运维 | 5 分钟 |

| | IP+端口 | 域名+443 |
|---|---|---|
| 用户看到的地址 | `http://111.53.208.218:8081` | `https://shop.xinyeonline.com.cn` |
| HTTPS | **做不了**（证书绑域名） | 一张通配证书全站通用 |
| 端口数量 | 十几个就抢完 | 无限制 |
| 换后端 | 改 DNS，缓存几小时 | 入口改一行，DNS 不动 |
| 等保备案 | IP 直连不认 | 认 |

**域名规划**：统一一级子域 `<项目>.xinyeonline.com.cn`（通配证书已覆盖，新增不签证书）；⚠️ 不用二级子域（通配符只匹配一级）；多前端用路径区分（`/admin`、`/api`）。临时调试可用 IP+端口，正式服务必须域名。

**新增路由为什么不重启**：静态配置（监听口/证书）要重启，一年几次放维护窗口；业务路由规则**热加载**。首选 K8s `IngressRoute`（kubectl apply 秒级生效，回滚即删对象）；备选 `traefik-routes` 目录挂载 + 按业务拆文件自动 reload；⛔ 禁止 ConfigMap + subPath 挂单文件（subPath 永不更新，只能删 Pod 重建，一次语法错全站 404——10-23 事故）。四层服务（数据库/TCP/MQTT）不进 Traefik：MetalLB 分 VIP + LoadBalancer，或只在内网经堡垒机访问。

### 5.13 专线与带宽扩展

**签约口径（2026-11-12 移动口头反馈）**：**对称 100M 专线**（上下行各 100 Mbps = 理论 12.5 MB/s）。⚠️ 口头反馈不作数，**以合同产品页为准**——要拿到三样：产品名称（互联网专线/商务快线）、上下行签约速率、SLA 条款。

**实测核验（2026-11-11/12，锐捷下挂终端）**：

| 项 | 实测值 | 与"对称 100M"的关系 |
|---|---|---|
| 出口 IP | 111.53.208.218（太原·移动） | 与合同一致 |
| **下行** | **127–130 Mbps 稳定跑满**（大文件直连 4 样本，6 线程并行无增益，此即链路上限） | ✅ **吻合**——100M 档超放至 ~1.25×（128M=16MB/s 整）是运营商常规做法，签约 100M、放行 128M 自洽 |
| **上行** | **国内对端（测速网 www.speedtest.cn · 太原联通节点）实测上传 140.85 Mbps**；早期单线程跨境 3.3M、多线程跨境 17–30M 均为**测试方法假象**（单 TCP 流跨境吞吐 / 跨境瓶颈），已废弃 | ✅ **对称证实**——与下行 138.93 同级，上下行相等，"对称 100M 专线"成立 |
| Ping 到入口 | 7–17 ms | 线路本身健康 |

**上行 100M 的验证方法（按优先级）**：① **合同/移动后台**——最权威；② **国内对端实测**——借一台国内云主机（阿里云 39.106.198.111）建 SSH 反向隧道，从云上下载机房文件，测出的即是真实上行；③ 机房内 cp2 跑 Ookla CLI 指定国内节点；④ 割接后防火墙/锐捷看端口 95 峰值长期观测。⚠️ 境外测速节点（台湾/韩国/蒙古）对上行只能给下界，不能用其低于 100M 的结果否定签约值。

**结论（2026-11-12 已钉死）**：**对称 100M 专线证实**——国内对端实测下载 138.93 / 上传 140.85 Mbps（100M 档超放 ~1.4×，上下行相等），时延 5ms / 抖动 0.56ms，线路质量优。原"10M""非对称宽带"口径全部作废。上行 100M+ 对外容量充裕（≈17.5 MB/s），"找移动扩上行"待办销除；跨境测速节点（台湾/韩国/蒙古）对上下行都只能给下界，不可用其结果判定签约值。

**上/下行哪个卡，找谁升**：

| 场景 | 动作 |
|---|---|
| 对外响应慢、页面大、项目变多 | 升带宽（IP 保留，防火墙不动，无割接）；当前 100M+ 余量大，短期内无此需求 |
| 内部拉镜像/下大文件慢 | 下行 140M 放行，不用动 |
| 要 99.9% 可用性 | 加第二条专线（换运营商），防火墙加板卡 |
| 视频/大文件对外 | 对象存储 + CDN，不走专线 |

**开工前用移动合同核实三件事**：①产品类型（大概率"企业宽带给固定 IP"，确认有没有 SLA）；②上行扩容价格与同纤可行性；③升档后静态 IP 111.53.208.218 是否保留（要改则先把 DNS TTL 调到 300 秒）。

⚠️ 锐捷 Reyee 管理界面**看不到签约带宽**：首页"上传/下载速度"只是实时流量；"上网设置"里如有带宽字段，那是 QoS 手填值，都不代表运营商给的带宽。确认带宽只有两条路：实测（本节方法）+ 合同。

⚠️ 防火墙 7 口已全部分配（GE1/0/4 是 DMZ 预留，可临时借用但要放弃 DMZ），加专线需**加网络板卡**（采购时预留扩展槽位），但集团网/iKuai/办公核心/研发网零改动；别接 iKuai（会把集团上网和私有云发布搅在一起）。

**每新增一条专线 7 步**：① 运营商开通（静态 IP/网关/掩码）② 光端机加一路 → 防火墙扩展 WAN 口（加板卡）③ 配 WAN 地址（不覆盖原默认路由，走策略路由）④ 配源地址策略路由（内网段 → 新 WAN）⑤ DNAT 新 IP:443 → 入口 VIP ⑥ DNS 加 A 记录 ⑦ 验证出向源 IP、入向 443、证书 CN、回程不丢包。

**三个坑**：多线必须配源地址策略路由（否则 A 出 B 回，运营商丢包，"ping 得通 TCP 建连失败"）；每条线绑一组业务；DNS TTL 调 300 秒（换线 5 分钟切完）。
