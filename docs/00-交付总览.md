## 一、这是什么

一个**部署在企业内网的文档问答系统**：员工上传公司文档（制度、手册、周报等），
用自然语言提问，系统从已入库文档里找依据并给出答案，**每条结论都带页码级引用**；
查不到就明确说查不到，不编。

一句话定位：**它不是"更聪明的搜索框"，也不是"通用聊天机器人"，它是"有据可查的内部问询台"。**

## 三、系统边界

### 做什么

- 单份文件上传（PDF / TXT / MD / CSV），自动解析、切片、向量化、入库
- 混合检索：语义向量 + 中文关键词，双路召回后融合重排
- 带引用回答：结论后标 `[1]`，附文档标题与页码
- 严格拒答：检索分数低于阈值直接说查不到
- 部门级权限：同一文档可设 私有 / 部门 / 全公司
- 流式输出（SSE），前端可逐字显示

### 不做什么（P0 明确排除，别指望）

- ❌ 不解析扫描件/图片型 PDF（无 OCR）
- ❌ 不处理视频、音频（方案里有，代码没有）
- ❌ 不自动爬取、不同步企业网盘、不监控目录
- ❌ 不做多轮对话记忆（每次提问独立）
- ❌ 不做文档生命周期管理（无删除接口，只能走 SQL）
- ❌ 不做 SSO / 无密码登录（当前是 Bearer Token）
- ❌ 没有正式前端（只有单页验收台）

完整清单见 [08-已知限制与风险.md](08-已知限制与风险.md)。

## 六、三分钟自检

不用读全文，跑这三条就知道系统还活着：

```bash
# 1. 四个容器是否都在
ssh <user>@<host> 'cd ~/kb-deskpet && docker compose ps'

# 2. 应用与模型服务是否健康
curl -s http://<host>:9527/api/health
curl -s http://<host>:8090/health      # 若在宿主机执行；容器内用 127.0.0.1

# 3. 问一个已知答案的问题，看是否带引用
curl -sN -X POST http://<host>:9527/api/query \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"question":"<库里确实有的问题>"}'
```

期望：`/api/health` 里 `db:"ok"`、三项 `configured`；问答返回带 `[1]` 的答案和 `citations` 事件。

## 八、交接必读的三件事

1. **`.env` 不在版本库里**，且包含真实 key。换机器部署必须重新配置，不能从 git 恢复。
2. **开机自启已配**（`restart: unless-stopped`），但**前提是 Docker 守护进程本身开机自启**。
   这点必须单独确认：`systemctl is-enabled docker`。历史上有项目因缺这一环停摆 48 小时。
3. **不要在没跑过 [07-验收标准](07-验收标准.md) 的情况下对外宣布"上线"**。当前状态是
   "技术验证通过"，不是"业务验收通过"。
