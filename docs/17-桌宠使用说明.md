# 17 · 知识小助（桌宠）使用说明

> **面向谁**：用「知识小助」桌面客户端提问、存资料的普通员工；发安装包和开账号的部门管理员请看附录 B。
> **最后更新**：2026-11-07 ｜ **对应版本**：v0.8.21（当前正式版）
> **前置条件**：管理员已经给你开好知识库账号。桌宠不是网页，不需要打开浏览器、也没有「访问口令」。

> ⚠️ 本文只描述**当前客户端里真实存在的功能**。旧文档 [09-使用手册](09-使用手册.md) 写的是浏览器版（访问 `http://…:9527` + 访问口令），**已不适用于桌宠**，请勿照它操作。

---

## 0. 一分钟上手

| 想做什么 | 怎么做 |
|---|---|
| 问一句 | 点屏幕右下角的小桌宠 → 打开面板 → 输入问题 → 按 `Enter` |
| 存一份资料 | 把文件拖进窗口（或直接拖给小桌宠）→ 在「存入知识库」里确认清单 → **点「存入」** |
| 只想拿一份文件问一次、不入库 | 拖进来时松在「就问这一次 / 用它回答我」那一半 |
| 看传到哪了 | 面板聊天区下方的「上传队列」；小桌宠头顶气泡也会显示 `上传中 2/5` |
| 收起面板 | 点右上角 `×` 或按 `Esc`（**只是隐藏，程序还在运行**） |
| 彻底退出 | 右上角 `⋯` → 「退出应用」 |

> **最容易搞错的一点**：文件拖进来**只是暂存，不会自动上传**。桌宠身上那句「松手就入库」是早期提示语，实际行为是「拖进来 → 看清清单 → 点『存入』才上传」。界面里的正式说明是「先放进来，看清了再存 —— 不会替你自动上传」，以这句为准。

## 1. 这个程序长什么样：两个窗口

| 窗口 | 长相 | 作用 |
|---|---|---|
| **桌宠**（小窗口） | 屏幕右下角一只透明的小形象，约 112×110，始终置顶、无边框、不占任务栏 | 常驻入口、拖文件、显示上传进度；会眨眼、思考、庆祝 |
| **问答面板** | 760×720 的无边框窗口，可拉伸（最小 480×520），**默认隐藏** | 登录、提问、看会话、选知识库、存入资料、看上传队列、检查更新 |

- 桌宠可以**按住拖动**到屏幕任意位置（拖动时它会倾斜一下）。
- **单击**桌宠（按下再松开、没有拖动）→ 打开问答面板。
- **右键**桌宠 → 显示 / 隐藏问答面板（它只是切换显隐，**不会弹出功能菜单**）。
- 关掉面板不会中断正在进行的上传；队列在程序内部统一维护，两个窗口同步进度。

## 2. 安装与首次启动

### 2.1 拿安装包

发布页：<https://github.com/buguanhuayue/kb-deskpet/releases/latest>（需要能访问该仓库；通常管理员会直接把安装包发给你）。

当前 v0.8.21 的产物：

| 平台 | 文件名 | 说明 |
|---|---|---|
| macOS（Apple Silicon / M 系列） | `_0.8.21_aarch64.dmg` | 约 8.4 MB |
| Windows（x64） | `_0.8.21_x64-setup.exe` | 约 6.0 MB，NSIS 安装包，简体中文 |
| 自动更新用 | `_aarch64.app.tar.gz`、`*.sig`、`latest.json` | 客户端自己下载，**不用手动取** |

> 目前只发布 **macOS Apple Silicon** 版；Intel Mac 需要单独构建，请联系管理员。

### 2.2 macOS 安装（⚠️ 必看）

1. 打开 `.dmg`，把「知识小助」**拖进「应用程序」文件夹**。
2. 从「应用程序」里启动它。

> **不要直接在 dmg 里双击运行**。程序不在 `/Applications` 里时无法原地替换，之后点「立即更新」会被拦下，并提示「当前程序不在「应用程序」文件夹里…先把「知识小助」拖进去」。这一步不做，自动更新永远失败。

首次打开若被系统拦下（"来自未识别的开发者"），在「系统设置 → 隐私与安全性」里点「仍要打开」，或右键图标选「打开」。

### 2.3 Windows 安装

双击 `_0.8.21_x64-setup.exe`，按提示装完即可。更新时采用静默（passive）安装：应用会先退出、装完自己重新打开。

### 2.4 首次启动

屏幕右下角出现小桌宠，未登录时它会提示「点我登录，把文件拖给我就入库」。点它打开面板，进入登录。

## 3. 登录

面板上「登录部门知识库」有三个输入框：

| 字段 | 填什么 |
|---|---|
| 服务器地址 | 默认已填 `https://knowledge.xinyeonline.com.cn`，**一般不用改**；管理员给了别的地址才改 |
| 账号 | 你的账号名（如 `zhangsan`），或完整邮箱（`zhangsan@company.local`） |
| 密码 | 管理员分配的密码 |

- 密码框里按 `Enter` 也能登录。
- 连不上时点「连不上？网络自检」，会去探测服务器的 `/health`。公司网络若拦了域名，先确认网络/VPN，再找管理员。
- 登录成功但一个知识库都看不到 → 提示「找管理员开通」，说明账号还没进组织 / 没分配知识库权限。
- 左下角侧栏底部会显示当前**账号**、**工作区**和**版本号**（如 `v0.8.21`）。

> 🔁 **重要：账号、空间或权限被管理员调整过（新建账号、换部门、修复过知识库绑定）之后，必须「退出应用」再重新打开并重新登录，不是关面板，也不是只点「退出登录」。** 旧登录信息里缓存着旧的工作区编号，不重登会导致上传全部失败（403）。这一条同样适用于刚装完新版本的用户。

## 4. 提问

1. 点桌宠打开面板，输入框在底部，提示语是「问点什么…（Enter 发送，Shift + Enter 换行）」。
2. 输入问题，按 `Enter` 或点「发送」。
3. 回答过程中会先看到「正在检索 N 个知识库…」，然后流式出答案（支持 Markdown 排版），末尾给出**引用**——点开引用条可以看原文片段，建议对关键结论点开核对。库里相关内容较少时，界面也会主动提示「这条答案建议点开引用核对原文」。

示例问题：`差旅报销的住宿上限是多少？`

- 答案卡片里还有「存一份相关资料」快捷入口，点了直接打开存入面板。
- `Enter` 发送，`Shift + Enter` 换行。
- 一段回答还没出完时不能切换知识库 / 提交资料，界面会提示「这条回答还没结束，等它答完再…」。
- 输入一大段文字时，界面会问你「这段更像资料 → 存进知识库 / 继续提问」，按意图选即可。
- 回答**不是只查你选中的那个库**，而是覆盖当前工作区里所有你能访问的库。顶栏会写清楚范围，见第 8 节。

## 5. 会话与侧栏

登录后左侧就是会话列表；顶栏 `☰` 可以显示 / 收起它（窗口拉窄到 660px 以下时，侧栏会变成带遮罩的抽屉，点空白处收起）。

| 操作 | 位置 |
|---|---|
| 新建对话 | 侧栏顶部「＋ 新对话」 |
| 搜索历史会话 | 侧栏搜索框「搜索会话标题…」 |
| 重命名 / 置顶 / 删除 | 每条会话右侧的 `⋯` 按钮 |
| 重命名快捷键 | `Enter` 提交，`Esc` 取消，点别处（失焦）也算提交 |

- 第一问之后服务端会异步生成会话标题，稍后列表会自动刷新。
- 会话列表滚动到底会自动加载更多。
- **临时附件绑定在会话上**：换会话或开新对话后，之前挂的附件会失效，需要重新拖一次。

## 6. 存入资料（核心功能）

### 6.1 四个入口

- 点输入框左侧的「**＋ 存入资料**」；
- 顶栏 `⋯` → 「存入资料…」；
- 直接把文件 / 文件夹从访达或桌面**拖进窗口**；
- 直接把文件**拖给小桌宠**（它会把清单转交给面板，并说「收到 N 个，去面板点『存入』」）。

### 6.2 拖进来时有两个落点

从窗口空白处拖入、且「存入」面板还没打开时，会出现两块落点，松手位置决定意图：

| 落点 | 文案 | 结果 |
|---|---|---|
| 左：**存入** | 「存进这个知识库 / 同事都能搜到」 | 进入待存入清单，等你点「存入」 |
| 右：**就问这一次** | 「用它回答我 / 不入库，24 小时后失效」 | 变成**本次提问的临时附件**，不写进知识库 |

> 临时附件只对这一问生效：答完自动撤掉；只挂了附件没写问题，系统会替你补一个默认问法；换会话即失效。落点上「24 小时后失效」是界面标注的口径。

### 6.3 两步原则（记这一条就够）

```
第 1 步  拖进来 / 选进来  →  进「暂存清单」（此时什么都没上传）
第 2 步  点右下角「存入」 →  才真正提交，聊天区才播报结果
```

「存入」面板里的正式提示也是这么写的：「把文件拖到这里 / 先放进来，看清了再存 —— 不会替你自动上传」。清单里每一项都能单独移除；「存入」按钮在没有内容时是灰的。

### 6.4 选目标知识库

「存入知识库」面板顶部是知识库下拉（显示当前库名 + 所属空间），右边 `⟳` 可刷新列表，`×` 关闭面板。

- 下拉**只列你能写入的库**（个人空间、可写的部门空间），按空间分组。
- 下拉里用 `↑` / `↓` 选择；`Esc` 关闭下拉 / 关闭存入面板。
- 默认优先选你**本人个人空间**里的第一个库。如果你自己的空间里一个库都没有，界面显示「请选择知识库」，**不会擅自替你选别人的库**，需要你手动挑一个。
- **换库有两种情况**（都不弹确认框，但正在回答时会拦下并提示「这条回答还没结束，等它答完再切」）：
  - 同一空间内换库 → 只改**上传目标**（提示「上传目标已切到 X」），检索范围和当前对话都不变；
  - 换到**另一个空间**的库 → 检索范围真的变了，会清空聊天区重新开始（提示「已切到「X」…回答改看这个空间的 N 个库」）。

### 6.5 三种资料来源

「存入」面板拖放区下方三个按钮：

| 按钮 | 用途 |
|---|---|
| 「选文件」 | 系统文件对话框，可多选 |
| 「选文件夹」 | 选整个目录，会递归收集里面的文件 |
| 「写一段文字」 | 弹窗填「标题」+「内容」，内容支持 Markdown，点「加入待存入」进清单 |

> 文字笔记是**同步提交**的，和文件上传分开播报；文件走队列异步处理。

### 6.6 点「存入」之后，你会看到什么

聊天区先给**入队回执**（不谎报成功）：

| 情形 | 系统消息 |
|---|---|
| 正常入队 | `已加入上传队列 N 项（库名），完成后在这里告诉你结果` |
| 有重复 | `另外 N 项已在队列或库里，跳过重复上传` |
| 文字笔记 | `已存入 N 条笔记到「库名」` |
| 提交阶段就失败 | `有 N 项没能提交成功，重试一次试试` |

等这一批条目全部有结果后，才在聊天区汇总**真实结果**。也就是说：「已加入上传队列」≠「已经能搜到」，请以下面的上传队列状态和最终汇总为准。

## 7. 上传队列

聊天区下方出现「上传队列 `完成数/总数`」，右上角有「清理已完成」。

### 7.1 状态含义

| 状态 | 含义 |
|---|---|
| `排队中` | 已入队，等前面的传完（同一时间只上传一个文件） |
| `上传中` | 正在把文件传给服务器 |
| `解析中` / `整理中` | 服务端在切片、向量化、生成摘要标签；会带耗时，如 `解析中 · 35s` |
| `已入库` | 完成，可以被同事搜到了 |
| `已存在` | 库里已有同名/同内容，跳过重复上传 |
| `失败 · 原因` | 出错，右侧给「重试」按钮；常见原因是超过 50MB、网络断开、登录过期 |

### 7.2 队列上的两个按钮

- 「**重试**」：只重传这一条失败的。
- 「**移除**」（出现在已入库条目上）：⚠️ **会真的把这一篇从知识库里删掉，同事将搜不到它**，需要二次确认。它用来纠正「拖错落点 / 存错库」，不是「从列表里隐藏」。

### 7.3 限制与行为

| 项 | 值 |
|---|---|
| 单文件大小 | ≤ 50 MB（本地先拦，避免白传） |
| 单批数量 | ≤ 500 个文件 |
| 文件夹递归 | 最多 8 层 |
| 并发 | 上传串行（一次一个）；解析在服务端并行进行 |
| 解析等待 | 最多轮询约 5 分钟；超时不会误判为失败，状态会继续保留 |
| 登录过期 | 会自动尝试刷新令牌，刷新失败才提示重新登录 |

队列由程序原生层维护，**收起面板、切到别的会话、甚至把面板关掉都不会中断上传**；小桌宠头顶气泡会同步显示 `上传中 2/5` / `解析中 2/5`，全部完成时报「已入库 N 份」，有失败时报「N 个没成功，点我看详情」。

## 8. 「检索范围」和「存入下拉」不是一回事

顶栏中间会显示类似：

```
回答基于 11 个库（2 个可存入 · 9 个只读共享）
```

| 概念 | 说明 |
|---|---|
| **检索范围**（顶栏那行） | 提问时会翻遍的所有库，**包含组织共享给你的只读库**；鼠标悬停可看库名清单 |
| **存入下拉** | 只列**能写入**的库，所以数量往往比顶栏少，这不是漏了 |
| **只读共享库** | 能检索、不能存入；顶栏会明确标出「R 个只读共享」 |

下拉分组包含「个人空间」「××部门」「其他空间（…）」等。**正常情况下不应该出现「其他空间」这一组**——如果它出现了，并且默认选中了别人的库，说明账号落到了错误的工作区，请按第 3 节「完全退出并重新登录」处理，并告知管理员。

## 9. 更多菜单、退出登录、退出应用

顶栏 `⋯` 打开菜单：

| 菜单项 | 作用 |
|---|---|
| 存入资料… | 打开「存入知识库」面板 |
| 打开网页端 | 用默认浏览器打开当前配置的知识库服务器地址 |
| 退出登录 | 清空本机登录信息、会话与暂存清单，回到登录页 |
| 退出应用 | **真正结束程序**（`app.exit(0)`） |

顶栏 `×` 只做一件事：**隐藏面板**，桌宠还在、上传还在跑。目前**没有系统托盘图标**，也没有「关闭到托盘常驻」的行为；想彻底结束请用「退出应用」。

`Esc` 的层级：先关文字输入弹窗 → 再关「存入」面板 / 知识库下拉 → 最后隐藏整个面板。

## 10. 自动更新

- **每次启动自动检查一次**（在原生态做，隐藏面板也会执行），有新版本时「检查更新」按钮上会有一个小红点，不会弹窗打断你。
- 手动检查：打开侧栏（☰）→ 左下角「**检查更新**」。已是最新会提示「已是最新版本 v0.8.21」。
- 有新版本时弹出「发现新版本 vX.Y.Z」卡片，显示当前版本、发布日期、更新说明，按钮为「稍后」/「立即更新」；下载时有进度条。
- **macOS**：下载完提示重启，重启后生效；程序必须放在「应用程序」里（见 2.2）。
- **Windows**：开始安装后应用会自动退出，装完由安装器重新拉起。
- 更新包带签名校验，校验失败会直接放弃安装，不会装上半个包。

### 常见更新报错

| 提示 | 怎么处理 |
|---|---|
| 「更新服务器上还没有可用的版本信息（latest.json 缺失或还没发布）」 | 通常发生在**新版本正在打包**：`latest.json` 要等 macOS 和 Windows 两个构建都成功、签名文件上传后才会生成。等几分钟再点「检查更新」即可 |
| 「连接更新服务器超时 / 连不上更新服务器」 | 公司网络可能拦了 `github.com`，连上可访问的网络再试 |
| 「没有写入权限：把「知识小助」拖到「应用程序」文件夹…」 | 见 2.2 |
| 「更新包校验失败，已放弃安装」 | 包损坏或被替换，重新下载 / 找管理员 |

## 12. 常见问题

**Q：我把文件拖进去了，为什么同事搜不到？**
A：拖进来只是暂存。打开「＋ 存入资料」，确认清单和目标知识库，点「**存入**」，再等队列状态变成「已入库」。解析（切片 + 向量化 + 摘要）需要一点时间。

**Q：上传队列里全是「失败」，或者提示 403 / 登录过期？**
A：按顺序试：① 看失败原因（最常见是文件超过 50MB）；② 点条目上的「重试」；③ 提示登录过期就重新登录；④ 如果整批都是 403，**完全退出应用 → 重新打开 → 重新登录**（见第 3 节）；⑤ 仍不行找管理员核对账号所属工作区。

**Q：「已加入上传队列」算成功吗？**
A：不算。那只是入队回执，真实结果要等这一批跑完后的汇总播报，或看队列状态。这是刻意这样设计的——以前会提前说「已提交成功」，结果失败了聊天区还留着成功提示，容易误导。

**Q：为什么顶栏说 11 个库，存入下拉只有 2 个？**
A：下拉只列能写入的库，其余 9 个是组织共享的只读库，能检索、不能存入。见第 8 节。

**Q：默认选中的知识库不是我的 / 名字是别人的？**
A：先「完全退出应用 → 重新登录」。如果仍然显示「其他空间（…）」分组并选中别人的库，说明账号的工作区绑定有问题，把截图发给管理员。

**Q：点了右上角 `×`，程序还在吗？**
A：还在，桌宠和上传都继续。要彻底结束请用 `⋯` → 「退出应用」。

**Q：换电脑 / 重装后要重新配置吗？**
A：要重新登录一次。登录信息、当前知识库、窗口侧栏状态都保存在本机。

## 13. 目前不支持 / 请勿依赖（明确边界）

以下事项**不要当成可用功能**写进操作习惯或培训材料：

| 项 | 实际情况 |
|---|---|
| `⌘⇧U` 全局快捷键 | 「＋ 存入资料」按钮的提示文字里写了这个组合，但程序**没有注册全局快捷键**，也没有对应的事件发送方。请用鼠标点按钮，或用 `⋯` 菜单 / 拖文件 |
| 「松手就入库」 | 小桌宠拖放时的旧提示语。**拖进来不会自动上传**，必须点「存入」 |
| 系统托盘 / 最小化到托盘 | 没有托盘图标；`×` 只是隐藏面板 |
| 粘贴截图 / 剪贴板图片入库 | 相关接口是占位实现，恒返回「剪贴板里没有图片」；请用「选文件」或「写一段文字」 |
| 「去开『本地网络』权限」按钮 | 默认隐藏，且网络自检结果里没有触发它所需的字段，正常不会出现 |
| 截图演示 / 冒烟测试模式 | 只有内部监听，没有面向用户的入口 |
| 浏览器访问 + 访问口令 | 那是旧网页版（见 09-使用手册），桌宠用账号密码登录 |
| 扩展名白名单 | 客户端没有按后缀过滤；能否解析取决于服务端支持的文件类型 |

## 附录 B · 管理员须知（普通员工可跳过）

1. **账号必须走组织模型**。新建账号时应具备四件套：本人 workspace（home tenant）的 `tenant_members` owner 行、`organization_tenant_members` editor 行、`preferences.last_active_tenant_id` 指向 home、在 home 下建本人同名知识库并 `kb_shares` viewer 共享给组织。只插老式「双 `tenant_members`」会让人登录落到部门主租户，把别人的库当成个人空间、还被盲选成默认上传目标。建号脚本见 `deliverables/weknora-scripts/add_user.py`（已改为组织化建号，支持 `--dry-run`）。
2. **客户端上传只发登录身份自己的租户**，跨租户写入靠服务端组织共享授权（`kb_shares` + `organization_tenant_members`）放行；不要给客户端配「共享库属主租户」，否则必然 403。
3. **调整账号 / 空间 / 权限后，通知用户「完全退出应用再重新登录」**。旧 `deskpet_cfg_v2` 里缓存的 `homeTenantId` 不会自动失效，不重登会复发 403。
4. **`latest.json` 是 CI 最后一个 job 生成的**，刚打完 tag 的几分钟内检查更新会报「latest.json 缺失或还没发布」，属正常构建窗口，不用重发。
5. 旧 `docs/09-使用手册.md` 描述浏览器版，已过时；如要保留，建议在其开头加一行指向本文的废弃说明。
