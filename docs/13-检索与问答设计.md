# 13 · 检索与问答设计

> 面向：开发、算法调优、要判断"为什么答不准"的人。
> 这份文档是全系统最需要"讲清原理"的部分——因为**90% 的答不准，根因在检索，不在模型**。
>
> 版本：v1.0 ｜ 对应参数：`53effe6` ｜ 最后更新：2026-10-31

## 一、问题定义

用户问"住宿费能报多少"，文档里写的是"住宿费上限五百元/晚"。三种做法：

| 做法 | 结果 | 问题 |
|---|---|---|
| 纯关键词（BM25/tsvector） | 搜"住宿费"能中，搜"住宿舍标准"不中 | 词不一致就废 |
| 纯向量 | 语义能中，但工号、制度编号、型号会漂 | 精确串不可靠 |
| **混合 + 重排** | 两路互补，重排裁决 | 组件多、参数多 |

**结论**：企业内部问答同时存在"术语不一致"和"精确串必须命中"两类需求，
单路必有一类失效，所以必须双路。这也是本设计存在的理由。

## 二、链路总览

```
问题
 │
 ├─(A) jieba 分词 + 去停用词 ──▶ to_tsquery('simple', '词1 | 词2 | ...')
 │                                        │
 │                                        ▼
 │                              关键词路：ts_rank_cd 取 40
 │
 └─(B) embedding（1024 维）──▶ 向量路：余弦距离取 40
                                 │
                    ┌────────────┴────────────┐
                    ▼                         ▼
              RRF 融合：Σ 1/(60+rank)     （无向量时只跑关键词路）
                    │
                    ▼
              重排（cross-encoder）对 top-N 逐条打分
                    │  失败 → 保留 RRF 排序
                    ▼
              拒答闸门：best.score < 0.35 ？
                    │ 是                    │ 否
                    ▼                       ▼
              直接拒答（不调 LLM）     拼 top-5 上下文 → 流式生成 → 附引用
```

## 三、切片：检索的上限

**切片粒度比换模型重要。** 切太大，一个切片混三个主题，向量被平均掉；
切太小，一句半句没有上下文，模型无法作答。

### 3.1 三条规则

| 规则 | 值 | 为什么 |
|---|---|---|
| 不跨页合并 | 一个切片只属于一页 | 保证 `{"page":n}` 永远准确；跨页就无法给页码 |
| 目标长度 | 300–500 字 | 中文制度条款通常 2–5 句，这个区间一段一主题 |
| 重叠 | 同页相邻 80 字 | 防止答案正好被切在边界 |
| 尾块 | > 4 字保留，过短则同页并入上一块 | 曾用 20 字阈值，导致短章节整页被丢 |

### 3.2 切分算法

1. 按空行/换行切段；
2. 段长 ≤ 500 → 直接作为候选段；超长 → 按 `。！？；!?;` 切句，句内不切；
3. 顺序累加候选段，达到 300 字即落块；超过 500 字强制落块；
4. 落块后保留尾部 80 字作为下一块开头；
5. 遍历结束，尾块 > 4 字则保留（同页可并入上一块，跨页不并）。

### 3.3 已知边界

- 表格被当纯文本，行列关系丢失（L10）；
- 双栏 PDF 可能左右栏交错；
- 条款极短的制度（每条 30 字）会切得过碎，需要按真实文档调 `MIN_CHARS`。

## 四、关键词路

### 4.1 为什么不能用 PG 默认中文分词

PostgreSQL 的 `simple` 配置按空格/标点切词，中文整句会被当成一个 token，
`tsvector` 里几乎没有可用词项；`zhparser` 需要编译扩展，运维成本高。

**本项目方案**：应用层 jieba 切词 → 空格连接 → 交给 `simple`。
入库与查询共用 `search/tokenize.py`，只改一边会导致检索静默归零（踩过）。

### 4.2 查询构造：为什么是 OR 不是 AND

```
to_query("住宿费的报销标准是多少")
→ "住宿费 | 报销 | 标准"        # 停用词"的/是/多少"被剔除
```

- `plainto_tsquery` 默认 AND 语义：切 5 个词，缺 1 个就整条 0 结果。中文场景几乎必踩。
- 改 `to_tsquery` + `|` 后，`ts_rank_cd` 按命中词数与密度排序，多命中的排前。

### 4.3 停用词表

内置 30 余个疑问/虚词（的、了、怎么、如何、什么、请问……）。
**只对查询去停用，入库不去**——入库保留原文可提高短语命中率。

## 五、向量路

| 项 | 值 | 说明 |
|---|---|---|
| 模型 | `jinaai/jina-embeddings-v3` | 1024 维，多语言，本地推理 |
| 距离 | 余弦（`<=>`） | `cosine = 1 - distance` |
| 索引 | HNSW `m=16, ef_construction=64` | 十万级切片足够 |
| `ef_search` | 默认 40 | 召回不够时**会话级**调大，不重建索引 |
| 候选数 | 40 | 与关键词路对称 |

**向量化文本**：切片正文（不含标题）。标题单独入库但不拼进向量——
标题重复度高会污染语义。若后续发现"标题含关键信息"的文档答不准，
可改为 `标题 + 正文`，但需全量重跑。

**批处理**：入库时每批 8 条，单条约 1.5 s，批 8 条约 2 s。

## 六、融合：RRF

### 6.1 公式

对每一路取前 `C=40`，第 `r` 名（从 1 开始）贡献 `1/(k+r)`，`k=60`：

```
RRF(d) = Σ_{路 ∈ {vec, kw}} 1/(60 + rank_路(d))
```

- 同一个切片被两路同时召回 → 分数叠加，自然排前；
- 只被一路召回 → 仍有分数，不会丢；
- **不需要归一化**：余弦是 0–1，`ts_rank_cd` 是无界值，直接加权会打架，RRF 只看排名就绕开了这个问题。

### 6.2 参数

| 参数 | 默认 | 调大的效果 | 调小的效果 |
|---|---|---|---|
| `CANDIDATES` | 40 | 召回更全，重排更慢 | 快，但长尾答案丢失 |
| `RRF_K` | 60 | 排名差异被抹平，更"民主" | 头部更集中，第一名单路说了算 |

### 6.3 为什么不用加权分数融合

`ts_rank_cd` 的量纲随查询长度变化，余弦固定在 0–1。做 min-max 归一化后加权，
权重会随查询漂移，且需要标注数据来学权重——当前没有标注，不做。

## 七、重排

| 项 | 值 |
|---|---|
| 模型 | `jinaai/jina-reranker-v2-base-multilingual` |
| 输入 | `(问题, 每个候选切片文本)` |
| 输出 | 相关性分数（0–1 量级），按分数降序 |
| 失败 | 返回空 → 保留 RRF 顺序，日志 warning |
| 作用 | ① 决定 top-5 谁进上下文 ② **作为拒答闸门的分数来源** |

**为什么必须有重排**：RRF 只反映"两路排名"，不反映"这段文字是否真的回答了问题"。
重排是唯一对"问题-片段"做联合建模的环节，也是拒答阈值唯一有区分度的分数。

**降级后果**：重排不可用时闸门退化为余弦 0.30。余弦区分度低
（相关 0.571 / 无关 0.030 是极端样例，真实分布会重叠），误判率上升。
所以重排不可用时应视为"可用但质量下降"，不能当成正常状态。

## 八、拒答闸门

### 8.1 判定顺序

```python
if not hits:                      return True          # 一条没召回
if best.rerank is not None:       return best.rerank < 0.35
if best.cosine is not None:       return best.cosine < 0.30
return False
```

**为什么用"最佳单条"而不是平均分**：只要有一条能支撑答案就够了；
平均分会被 4 条无关片段拉低，造成误拒。

**为什么闸门在生成前**：把"有没有"交给模型判断，等于把确定性变成概率。
本项目实测：库外问题 `top_score=0.1752`，闸门直接拦下，**没有调用生成模型**。

### 8.2 阈值 0.35 的来历（必须知道它多脆弱）

- 样本量：**2 条**（1 正 0.7574，1 负 0.1752）；
- 取法：两点之间取偏保守值；
- 结论：**这个数没有统计意义**，只能保证"极端情况不误判"。

### 8.3 重新标定方法（接入真实文档后第一件事）

1. 用 20 个"库里确实有答案"的问题，记录 `top_score`，取 **P10** 作为下限候选；
2. 用 10 个"库里没有"的问题，记录 `top_score`，取 **P90** 作为上限候选；
3. 若 P10 > P90 → 有清晰分界，阈值取中点；
4. 若 P10 ≤ P90 → **分布重叠，说明检索质量不够**，先调切片与候选数，不要硬调阈值；
5. 定值后写回 `.env`，并在 [07](07-验收标准.md) 记录样本量与分布。

### 8.4 误拒 vs 漏拒的取舍

| 选择 | 用户体验 | 业务风险 |
|---|---|---|
| 阈值偏高 | "明明有却说没有" | 低（不会编） |
| 阈值偏低 | "答得挺顺但答错了" | **高（错答比不答危害大）** |

**默认选偏高。** 这是产品定位决定的：内部制度问答里，一次错误金额的代价远大于十次"请换个说法"。

## 九、上下文与提示词

### 9.1 上下文拼装

```
[1] 《差旅与休假制度》 第 3 页
<切片原文>

---

[2] 《报销管理办法》 第 1 页
<切片原文>
```

- 只放 `TOP_K=5` 条，按重排分降序；
- 每条带标题与页码，模型才能标对引用编号；
- 不截断切片正文（切片本身已 ≤ 500 字），避免答案被截半。

### 9.2 系统提示词（五条规则，逐条有理由）

| 规则 | 防的是什么 |
|---|---|
| 只用【资料】回答，没有就说没查到 | 模型用参数记忆补全（幻觉主因） |
| 每个结论标 `[n]` | 无法核对 = 无法追责 |
| 资料矛盾时并列两种说法 | 模型替用户裁决会掩盖文档冲突 |
| 先结论后细节，不复述问题 | 企业用户要的是答案不是作文 |
| 数字/金额/日期逐字照抄 | 改写"五百元"成"约 500 元"会失真 |

**提示词不是闸门。** 规则降低幻觉概率，但只有代码级闸门能保证"查不到就不答"。

### 9.3 引用生成

引用不是让模型"写"出来的，而是**由检索结果结构化生成**：

```json
{"index":1,"doc_id":"...","title":"差旅与休假制度",
 "locator":{"page":3},"locator_text":"第 3 页",
 "snippet":"……","score":0.7574}
```

模型只负责在正文里写 `[1]`，映射关系由服务端保证。这样即使模型编号写错，
前端点 `[1]` 仍能打开真实来源——**引用可核对性不依赖模型**。

## 十、参数总表

| 参数 | 位置 | 默认 | 安全范围 | 改动风险 |
|---|---|---|---|---|
| `MIN_CHARS` | `chunker.py` | 300 | 150–400 | 改大→切片变少变粗；改小→碎片化 |
| `MAX_CHARS` | `chunker.py` | 500 | 300–800 | 超过模型有效窗口，语义被稀释 |
| `OVERLAP` | `chunker.py` | 80 | 40–150 | 过大→重复召回、上下文浪费 |
| `CANDIDATES` | `.env` | 40 | 20–100 | 过大→重排变慢（线性） |
| `RRF_K` | `.env` | 60 | 20–100 | 影响头部集中度 |
| `TOP_K` | `.env` | 5 | 3–8 | 过大→上下文噪声、成本上升 |
| `NOT_FOUND_THRESHOLD` | `.env` | 0.35 | 0.2–0.6 | **误拒/漏拒直接来源** |
| 余弦兜底 | `answer.py` | 0.30 | 0.25–0.40 | 仅在无重排时生效 |
| `ef_search` | 会话级 | 40 | 40–200 | 调大→召回升、延迟升 |
| `EMBED_DIM` | `.env` | 1024 | **锁死** | 改动必须全量重跑 |

## 十一、调优手册（按症状查）

**顺序原则：先切片 → 再候选数 → 再阈值 → 最后才换模型。**
换模型是最后手段，因为要全量重跑且不可逆。

| 症状 | 最可能原因 | 处理顺序 |
|---|---|---|
| 明明有答案却拒答 | 阈值偏高 / 切片把答案切断 / 候选没召回 | ① 看 `top_score` 与原文位置 ② 调 `CANDIDATES` ③ 调切片 ④ 最后降阈值 |
| 答非所问，但引用存在 | 重排失效或 top-1 是"相关但不回答" | ① 查重排是否 501 ② 看 top-5 是否含正确片段 ③ 调 `TOP_K` |
| 专有名词搜不到 | 分词切错 / 关键词路权重不足 | ① 加 jieba 自定义词典 ② 检查 `to_query` 输出 |
| 答案漏掉后半段 | 答案跨切片 | ① 加大 `OVERLAP` ② 检查是否跨页被切开（跨页不并是硬约束） |
| 页码对不上 | 切片跨页 / 解析错位 | ① 查 chunker 是否跨页合并 ② 抽样核对 PDF 原文 |
| 全是"知识库里没有" | 向量服务挂了 / 检索 SQL 报错 | ① `/api/health` ② 看日志 ③ 确认 `tsv` 非空 |
| 回答正确但没标引用 | 提示词被截断 / 上下文超长 | ① 减 `TOP_K` ② 检查模型上下文上限 |

## 十二、评测设计

### 12.1 题目结构（目标 30 题）

| 类型 | 数量 | 目的 | 判定 |
|---|---|---|---|
| 事实查找 | 12 | 常规可用性 | `expect_doc` 在 top-5 |
| 数字/金额/日期 | 6 | 精确性（最易出错） | 命中且答案数字一致 |
| 术语不一致 | 6 | 语义路是否有效 | 命中（字面不重叠） |
| 库外问题 | 6 | 拒答闸门 | `refused=true` |

### 12.2 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| recall@5 | 正确文档出现在前 5 的比例 | ≥ 85% |
| 拒答准确率 | 库外问题被正确拒答的比例 | ≥ 95% |
| 误拒率 | 库内问题被判拒答的比例 | ≤ 5% |
| 引用正确率 | 标注页码确实包含该结论 | ≥ 98% |
| P95 首字节 | 提问到第一个 token | < 3 s |

### 12.3 标注纪律

1. **先有文档再出题**，不许凭想象出题；
2. 每题必须写 `expect_doc`（标题关键字），否则无法自动判分；
3. 库外题必须是"公司语境下合理但文档确实没有"，不能用"明天天气"凑数
   （太离谱的负例会让闸门看起来很好）；
4. 每次改切片/阈值/模型，**全量重跑并记录**，不允许只跑"感觉相关"的几题。

### 12.4 当前状态（诚实记录）

- 题目：8 题（5 正 + 3 负），**不足 30**；
- 已跑：端到端 2 题（1 正 1 负），均符合预期；
- 结论：**当前没有任何统计意义上的准确率**，只能说"链路通"。

## 十三、已知不足与演进方向

| 不足 | 影响 | 演进 |
|---|---|---|
| 无 query 改写 | 口语化长问句召回差 | 用 LLM 改写成 2–3 个检索式，多路召回 |
| 无父子块 | 小块准但上下文少，大块全但噪声多 | 子块检索、父块喂给模型 |
| 无混合权重学习 | RRF 是启发式 | 有标注后学加权或接 LTR |
| 表格未结构化 | 表格问答差 | 表格单独解析为 markdown 再切 |
| 无多语言 | 英文文档效果未知 | jina-v3 本身多语言，需实测 |
| 阈值单点 | 不同文档类型分布不同 | 按文档类型分阈值（需数据支撑） |

**最后一句**：这套链路的上限由**文档质量与切片质量**决定，不由模型决定。
在没接入真实文档之前，任何"再换个更强的模型"的想法都是错的方向。
