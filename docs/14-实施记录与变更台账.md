## 四、缺陷台账

按发现顺序编号，全部已修复。**"复发风险"一列是给接手人的警告**。

| ID | 现象 | 根因 | 修复 | 复发风险 |
|---|---|---|---|---|
| **D-01** | 中文检索整条归零：切 5 个词，缺 1 个就 0 结果 | `plainto_tsquery` 默认 AND 语义 | 改 `to_tsquery('simple', 'a \| b \| c')` + `ts_rank_cd` 排序 | 高——谁把 OR 改回 AND 就复发，且不报错 |
| **D-02** | 短章节整页被丢弃（几十字的条款消失） | 尾块阈值 20 字，短章不足 20 字 | 阈值降到 4 字，过短同页并入上一块 | 中——调切片参数时容易改回去 |
| **D-03** | 本地 venv 创建/安装异常退出 | 字节码写入与并发安装冲突 | `PYTHONDONTWRITEBYTECODE=1` 重建 | 低 |
| **D-04** | 删文件失败导致接口 500 | `storage.delete` 未捕获异常 | try/except + logger，删除失败不阻断主流程 | 低 |
| **D-05** | 容器内迁移脚本找不到 `migrations/` | `parents[2]` 在容器里算出 `/migrations` | 候选探测：`MIGRATIONS_DIR` → `/app/migrations` → `<repo>/migrations` | 中——镜像目录结构一变就复发 |
| **D-06** | 迁移报 `UnicodeDecodeError: 0xa3` | macOS 打包带入 `._0001_init.sql`（AppleDouble 二进制） | `COPYFILE_DISABLE=1` + `--exclude='._*'` + 运行时跳过 `._` + 解包后清理 | 中——用 macOS 打包就会复发 |
| **D-07** | 容器内读文件报编码错误 | slim 镜像默认 locale 非 UTF-8 | `read_text(encoding="utf-8")` + `LANG=C.UTF-8` + `PYTHONUTF8=1` | 低 |
| **D-08** | 远程执行脚本时标准输入被吞，后续命令不执行 | `docker compose exec -T` 消费了 stdin | 统一 `</dev/null`；脚本 scp 成文件再执行 | 高——写部署脚本时最容易再犯 |
| **D-09** | worker 每 2 秒崩溃一次，日志刷 `NoneType` | `claim_job()` 返回复合类型，空队列时返回"一行全 NULL" | 迁移 `0002` 改 `RETURNS SETOF jobs`；worker 判 `job["id"] is None` | 中——改函数返回类型时注意 |
| **D-10** | 应用 `0002` 报 `cannot change return type` | `CREATE OR REPLACE` 不允许改返回类型 | 先 `DROP FUNCTION IF EXISTS claim_job()` | 低 |
| **D-11** | 目标机 `.env` 被覆盖，key 与端口全丢，服务起不来 | `rsync` 传 `.` 时同步了本机 `.env` | 重写 `.env`；Makefile 加 `make sync` 显式 `--exclude=.env` | **高——这是最危险的一类操作** |
| **D-12** | 本地向量模型加载失败 | fastembed 0.7.4 已移除 `BAAI/bge-m3` | 改用 `jinaai/jina-embeddings-v3`（同为 1024 维，DDL 不动） | 中——升级 fastembed 需重验模型清单 |
| **D-13** | 模型下载 401 / CAS 错误 | hf-mirror 的 xet 传输不兼容 | `HF_HUB_DISABLE_XET=1` | 中——换网络环境可能复现 |
| **D-14** | 新部署照 `.env.example` 配置后向量化必失败 | 模板仍写 bge-m3，与本地服务不兼容 | 模板改 jina 系列 | 低（已修） |
| **D-15** | 新机器启动就报向量服务 401/余额不足 | `config.py` 默认值指向云端硅基流动 | 默认改 `http://embed:8088/v1` | 低 |
| **D-16** | 主机重启后全站不可用 | 只配了容器 `restart`，没配 Docker 开机自启 | bootstrap 第 7 步 `systemctl enable docker` | 中——重装系统会丢 |
| **D-17** | 仓库里出现 `.envH2PiKw`（含真实 key） | 编辑器临时文件被 `git add .` 带入 | 删除文件；`.gitignore` 补 `.env*` 规则 | **高——secret 泄露不可逆** |

## 七、迁移实施记录

### 7.1 实际步骤

```
1. 本机 make pack            → dist/kb-deskpet-<ts>.tar.gz（排除 .env / .git / node_modules）
2. scp 到目标机              → /tmp/
3. bootstrap.sh              → 装 Docker / 配镜像源 / 解包 / 建卷 / 检查 .env / 迁移 / 启容器
4. make check                → 四项闸门
5. make seed                 → 演示账号与 Token
6. 局域网访问验证            → 9527 可打开、可提问
```

### 7.2 迁移中真实发生的事故

| 事故 | 过程 | 损失 | 处置 | 固化措施 |
|---|---|---|---|---|
| **`.env` 被覆盖** | 后续用 `rsync . host:~/kb-deskpet` 同步代码，把本机 `.env` 推过去，目标机的 key 与 `APP_PORT=9527` 被覆盖 | 服务起不来，排查 20 分钟 | 按记录重写 `.env`（600） | `make sync` 显式 `--exclude=.env`；文档反复强调 |
| **AppleDouble 污染** | macOS `tar` 带入 `._*.sql`，迁移脚本当 SQL 执行 | 首次迁移失败 | 清理 + 打包加 `COPYFILE_DISABLE=1` | 打包脚本与迁移脚本双重防护 |
| **stdin 被吞** | `ssh host "docker compose exec -T ... <<SQL"` 后面的命令不执行 | 误以为脚本成功 | 改 `</dev/null` + scp 脚本文件 | 部署脚本统一写法 |

**教训**：迁移不是"复制文件"，是"**复制状态**"。状态包括 `.env`、卷、模型缓存、Docker 自启配置。
只复制代码的迁移，第二次重启就会暴露问题。

## 八、取舍记录（当时为什么这么定）

| 决策点 | 选项 A | 选项 B | 选了 | 理由 |
|---|---|---|---|---|
| PDF 解析 | PyMuPDF（快、强） | pypdfium2（许可干净） | **B** | AGPL 商用有传染风险，不能给甲方埋雷 |
| 队列 | Redis + Celery | `jobs` 表 + SKIP LOCKED | **B** | 日均几十篇，不值得多两个组件 |
| 向量化 | 云端 API | 本地 fastembed | **B**（因余额耗尽被动转） | 转完发现更符合"数据不出网"，长期成本为 0 |
| 前端 | React | 单页验收台 | **B** | P0 目标是验证链路，不是做产品 |
| 权限 | 应用层过滤 | SQL 谓词 | **B** | 候选截断前过滤，物理上不可能越权 |
| 重排 | 不做 | 本地 cross-encoder | **B** | 拒答阈值需要区分度，RRF 分数不够 |
| 维度 | 768（更省） | 1024（模型默认） | **B** | 与 jina-v3 一致，避免截断/补齐损失 |

**被动决策要标注**：向量化本地化最初不是设计选择，是云端余额耗尽后的应急。
应急方案后来被证明更优（成本、合规），但**决策过程必须如实记录**，
否则下一个人会以为"当初就是这么设计的"，从而低估供应商风险。
