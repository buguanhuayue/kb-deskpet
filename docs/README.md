## 四、编号规则

- `00`–`09`：交付件（给甲方看的"成品说明书"）；
- `10`–`16`：生命周期文档（过程与决策留痕）；
- `17`：桌宠客户端使用说明（面向最终用户；09 为旧浏览器版手册，已过时）；
- 新增文档取下一个未占用编号，**不重排旧编号**（外部链接会断）；
- 过程记录不占编号，直接放 `docs/` 根。

## 五、维护约定

1. **改代码必须检查四份文档**：04（接口）、05（数据模型）、03（配置）、12/13（设计与参数）。
2. **改参数必须同时改**：`.env.example`、03、13 参数总表。
3. **改需求必须同时改**：10（需求条目）、07（验收口径）、15（用例）。
4. **修 P1 级缺陷必须进** 14 §4 台账，写清根因与复发风险。
5. **每份文档开头写"面向谁"和"最后更新"**，没有这两项的文档视为草稿。
