# 07 · 验收标准

> 面向：甲方、项目负责人、实施工程师。
> 用途：明确"交付完成"的客观定义，避免用"感觉还行"验收，也避免用"什么都能答"当作标准。

## 一、验收前置条件

验收前必须满足，否则测出来的是环境问题不是系统问题：

- [ ] 四个容器全部 `Up`，`postgres` 与 `embed` 为 `healthy`
- [ ] `/api/health` 返回 `db:ok` + 三项 `configured`
- [ ] `scripts/check_keys.py` 四项全绿（真实调用，非配置检查）
- [ ] **已接入至少 20 篇真实业务文档**（不是测试 PDF）
- [ ] `systemctl is-enabled docker` 为 `enabled`

> 第 4 条是关键。只有 1 篇测试文档时，任何指标都没有统计意义。

## 五、必须重新标定的参数

当前阈值基于 **1 篇文档 1 个切片**，统计上无意义。接入真实文档后必须重标：

| 参数 | 当前值 | 重标方法 |
|---|---|---|
| `NOT_FOUND_THRESHOLD` | 0.35 | 跑 20 个"库里有"问题记录 `rerank` 分布，再跑 10 个"库外"问题；阈值取两者分界处 |
| `TOP_K` | 5 | 试 3/5/8，看答案完整度与响应时长 |
| `CANDIDATES` | 40 | 若 recall@5 低，先试着调大这个 |
| 切片参数 | 300–500 字 / 80 重叠 | 看真实文档的条款长度分布 |

切片参数在 `server/app/ingest/chunker.py`，三个常量：`MIN_CHARS=300`、`MAX_CHARS=500`、`OVERLAP=80`。

## 六、评测集怎么跑

`eval/questions.yaml` 定义了问题、期望命中的文档关键字、以及"库里没有"的拒答题。

```bash
# 逐题调 /api/search，看 expect_doc 是否在前 5
python3 - <<'PY'
import json, urllib.request, yaml
BASE, TOKEN = "http://127.0.0.1:9527", "<token>"
qs = yaml.safe_load(open("eval/questions.yaml"))
hit = 0
for q in qs:
    req = urllib.request.Request(f"{BASE}/api/search",
        data=json.dumps({"question": q["question"]}).encode(),
        headers={"Content-Type": "application/json", "Authorization": f"Bearer {TOKEN}"})
    d = json.load(urllib.request.urlopen(req))
    titles = [h["title"] for h in d["hits"]]
    ok = (not d["count"]) if q.get("expect_none") else any(q["expect_doc"] in t for t in titles)
    hit += ok
    print(("✅" if ok else "❌"), q["question"][:24], titles)
print(f"\naccuracy = {hit}/{len(qs)}")
PY
```

**当前评测集只有 8 题，不满足"30 题"的验收要求。** 需要甲方用自己的真实文档补充。
