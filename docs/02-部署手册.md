# 02 · 部署手册

> 面向：运维 / 实施工程师。目标是从一台干净机器做到"能提问"。
> 全程约 20 分钟（首次含模型下载约 15 分钟额外等待）。

## 一、前置条件

| 项 | 最低 | 建议 | 说明 |
|---|---|---|---|
| CPU | 4 核 | 8 核 | 本地向量模型吃 CPU |
| 内存 | **8 GB** | **16 GB** | embed 容器常驻约 5.7 GB，这是硬门槛 |
| 磁盘 | 30 GB | 60 GB | 镜像约 2 GB + 模型 3.2 GB + 数据增长 |
| 系统 | Ubuntu 22.04 / 24.04 | 同 | Debian 12 也可，其他发行版需自行适配 |
| 架构 | x86_64 / arm64 | x86_64 | arm64 需确认镜像有对应 tag |
| Docker | 24+ 与 compose v2 | 29.x | `docker compose version` 必须能跑 |
| 出网 | 见下节 | — | 只需一次性，运行期仅生成模型需要 |

## 二、部署前必查（最容易卡在这里）

在目标机上逐条执行，**任何一条不通都要先解决再往下走**：

```bash
# 1) Docker Hub 是否可达（国内多数环境不通，必须配镜像加速）
curl -s -m 6 -o /dev/null -w "%{http_code}\n" https://registry-1.docker.io/v2/

# 2) 模型下载源是否可达（本地模型方案需要）
curl -s -m 6 -o /dev/null -w "%{http_code}\n" https://hf-mirror.com

# 3) 生成模型 API 是否可达
curl -s -m 6 -o /dev/null -w "%{http_code}\n" https://apihub.agnes-ai.com/v1/models
```

**第 1 条返回 000 是最常见的情况**，处理方式：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{
  "registry-mirrors": ["https://docker.m.daocloud.io", "https://docker.1ms.run"]
}
JSON
sudo systemctl restart docker
docker info --format '{{.RegistryConfig.Mirrors}}'
```

> 镜像站会失效，若上述两个都不通，换 `hub.rat.dev` / `dockerpull.org` / 阿里云个人加速地址。

## 三、步骤 1：获取代码

**方式 A：从打包产物部署（推荐，跨机迁移用）**

```bash
# 在源机
bash deploy/pack.sh                    # 生成 dist/kb-deskpet-migrate-<时间戳>.tgz
scp dist/kb-deskpet-migrate-*.tgz <user>@<host>:~/

# 在目标机
bash bootstrap.sh kb-deskpet-migrate-*.tgz
```

`bootstrap.sh` 做六件事：装 Docker（若缺）→ 解包 → 写 `.env` → `compose up -d --build`
→ 等 PG 就绪 → 迁移 → 自检。**幂等**，可重复执行；重复执行时 `.env` 和数据卷不受影响。

**方式 B：直接从 git 部署**

```bash
git clone <repo> ~/kb-deskpet && cd ~/kb-deskpet
cp .env.example .env && chmod 600 .env
```

## 四、步骤 2：配置 `.env`

编辑 `~/kb-deskpet/.env`。**必填项只有三组**，其余保持默认：

### 2.1 数据库密码（必改）

```ini
POSTGRES_PASSWORD=<强密码>
DATABASE_URL=postgresql://kb:<同一个强密码>@postgres:5432/kb
```

> 两处必须一致。第一处给 postgres 容器建库用，第二处给应用连接用。密码含特殊字符时
> `DATABASE_URL` 里要 URL 编码（如 `@` → `%40`）。

### 2.2 生成模型（必填）

```ini
LLM_BASE=https://apihub.agnes-ai.com/v1
LLM_MODEL=agnes-3.0-flash
LLM_API_KEY=<你的 key>
```

任何 OpenAI 兼容接口都行（DeepSeek、通义、自建 vLLM）。换供应商只改这三行。

### 2.3 向量化与重排（二选一）

**方案 A：本地模型（推荐，无外部依赖、无调用费）**

```ini
EMBED_BASE=http://embed:8088/v1
EMBED_MODEL=jinaai/jina-embeddings-v3
EMBED_API_KEY=local
EMBED_DIM=1024
EMBED_REQUIRED=true
RERANK_BASE=http://embed:8088/v1
RERANK_MODEL=jinaai/jina-reranker-v2-base-multilingual
RERANK_API_KEY=local
LOCAL_RERANK_MODEL=jinaai/jina-reranker-v2-base-multilingual
```

**方案 B：云端 API（机器配置低时用）**

```ini
EMBED_BASE=https://api.siliconflow.cn/v1
EMBED_MODEL=BAAI/bge-m3
EMBED_API_KEY=<key>
EMBED_DIM=1024
RERANK_BASE=https://api.siliconflow.cn/v1
RERANK_MODEL=BAAI/bge-reranker-v2-m3
RERANK_API_KEY=<key>
```

> ⚠️ **`EMBED_DIM` 必须与数据库列定义一致（1024）**。换模型前先确认其输出维度，
> 不一致会导致入库时报错，且已有向量全部作废。详见 [05](05-数据模型与权限.md#四向量维度不可随意更改)。
>
> ⚠️ 方案 B 若余额不足会返回 `402`，入库直接失败。若只想先跑通流程，可临时设
> `EMBED_REQUIRED=false`（无向量入库，仅关键词检索可用），但**此时拒答闸门失效**，
> 仅供联调，不可用于生产。

### 2.4 端口（可选）

```ini
APP_PORT=9527        # 宿主机端口；容器内固定 8088，只换映射
```

## 五、步骤 3：启动

```bash
cd ~/kb-deskpet
docker compose up -d --build      # 首次构建约 2-3 分钟
docker compose ps                 # 期望 4 个服务全部 Up（embed 首启会先 unhealthy）
```

首次启动时 `embed` 容器会下载约 3.2 GB 权重，`start_period` 给了 300 秒，
但慢网络下可能超过。观察进度：

```bash
docker compose logs -f embed      # 看到 "embedding 就绪 ... dim=1024" 即完成
```

## 六、步骤 4：验证（逐项打勾，不要跳）

```bash
# ① 容器状态
docker compose ps
# 期望：postgres (healthy) / embed (healthy) / api (Up) / worker (Up)

# ② 应用健康
curl -s http://127.0.0.1:<APP_PORT>/api/health | python3 -m json.tool
# 期望：db=ok，embed/rerank/llm 均为 configured

# ③ 模型服务健康
docker compose exec -T embed curl -s http://127.0.0.1:8088/health
# 期望：dim=1024, embed_ready=true, rerank_ready=true, *_error 为 null

# ④ 表结构
docker compose exec -T postgres psql -U kb -d kb -c '\dt'
# 期望：9 张表（含 schema_migrations）

# ⑤ key 自检（会真实调用一次各服务）
docker compose exec -T api python scripts/check_keys.py
```

`check_keys.py` 输出应为四项全 ✅。若有 ❌，按提示定位——它报的是**真实调用结果**，
不是"配了没配"。

## 七、步骤 5：建账号

```bash
docker compose exec api python scripts/seed.py
```

输出会打印一个 `Bearer token`，形如 `9gDXhxOD81yF_Ng4YBVbzFRG86o2leMq`。**记下来**，
后面登录验收台要用。同时创建了演示部门「综合部」与账号 `admin@local`。

> 生产环境请改用 `role=admin` 的正式账号，并把演示账号停用。当前无用户管理界面，
> 需直接写库（见 [05](05-数据模型与权限.md#六常用运维-sql)）。

## 八、步骤 6：首次入库与提问

```bash
TOKEN=<上一步的 token>
# 上传
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -F "file=@/path/to/制度.pdf" -F "title=差旅与休假制度" \
  http://127.0.0.1:<APP_PORT>/api/ingest/file

# 等状态变 ready（worker 轮询间隔 2 秒）
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:<APP_PORT>/api/documents

# 提问
curl -sN -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question":"住宿费的报销标准是多少？"}' \
  http://127.0.0.1:<APP_PORT>/api/query
```

也可以直接用浏览器打开 `http://<host>:<APP_PORT>`，通过单页验收台拖文件、提问。

## 九、步骤 7：开机自启（**必做，最容易漏**）

容器已配 `restart: unless-stopped`，但**前提是 Docker 守护进程本身开机自启**。
两步都要查：

```bash
sudo systemctl enable docker        # 关键：守护进程开机自启
systemctl is-enabled docker         # 期望输出 enabled
docker compose ps                   # 确认四个服务 restart 策略生效
```

验证方式（生产环境上线前必须做一次）：

```bash
sudo systemctl restart docker
sleep 15 && curl -s http://127.0.0.1:<APP_PORT>/api/health
# 期望 15 秒内恢复 db=ok
```

> 历史教训：同类项目因漏了 `systemctl enable docker`，机器重启后服务静默停摆 48 小时
> 无人发现，直到有人问"为什么打不开"。

## 十、常见部署失败

| 现象 | 根因 | 处置 |
|---|---|---|
| `docker pull` 卡住或 000 | Docker Hub 不可达 | 配 `registry-mirrors`（第二节） |
| `permission denied ... docker.sock` | 用户不在 docker 组 | `sudo usermod -aG docker $USER` 后重新登录 |
| embed 容器反复 unhealthy | 模型下载失败 | 看 `logs embed`；确认 `HF_HUB_DISABLE_XET=1` 已设 |
| 模型下载 401 / CAS 错误 | hf-mirror 的 xet 协议限流 | 必须 `HF_HUB_DISABLE_XET=1`，否则走 CAS 会 401 |
| `no migration found` | 迁移目录探测失败 | 确认 `MIGRATIONS_DIR` 或容器内 `/app/migrations` 存在 |
| 迁移报 `UnicodeDecodeError` | macOS 打包带入 `._*` 影子文件 | 用 `COPYFILE_DISABLE=1` 重新打包；或删掉 `._*` |
| `cannot change return type` | PostgreSQL 不允许改函数返回类型 | 迁移里先 `DROP FUNCTION` 再建 |
| worker 日志狂刷 `invalid input syntax for type uuid: "None"` | `claim_job()` 返回复合类型，空队列返回一行全 NULL | 已由 `0002` 迁移修复；若复现检查是否跳过该迁移 |
| `hello` 正常但 `/api/query` 401 | token 错或 users 表为空 | 跑 `seed.py`；检查 `Authorization: Bearer` 前缀 |
| 端口占用 | 宿主已有服务 | 改 `APP_PORT` |
| `no space left on device` | 模型 + 镜像 + 数据 | `docker system prune`；确认磁盘 ≥ 30 GB |

## 十一、部署形态对照

| | 一体化（当前） | 拆分（大规模时） |
|---|---|---|
| embed | 同机容器 | 独立 GPU 机器，改 `EMBED_BASE` 指向它 |
| postgres | 同机容器 | 独立数据库实例，改 `DATABASE_URL` |
| 适用 | 单部门、文档 < 5 万切片 | 多部门、高并发 |
| 改动量 | — | 只改 `.env`，代码不变 |

> 拆分是设计时就留好的口子：所有外部依赖都走 `*_BASE` 配置，没有硬编码地址。

## 十二、升级流程

```bash
cd ~/kb-deskpet
git pull                              # 或重新 rsync 代码
docker compose up -d --build          # 只重建变更的服务
docker compose exec -T api python scripts/migrate.py </dev/null   # 跑新迁移
```

**注意事项**：

- **不要**用 `docker compose down -v` —— `-v` 会删数据卷，数据全丢
- 迁移是幂等的，重复跑安全
- 升级前先备份（见 [06-运维手册](06-运维手册.md#三备份与恢复)）
- `.env` 不会被 `git pull` 覆盖，但**也不会被更新**——新增配置项需手工补
