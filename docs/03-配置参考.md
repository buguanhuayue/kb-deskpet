# 03 · 配置参考

> 面向：运维、开发。所有配置集中在仓库根目录的 `.env`（**不在版本库里**）。
> 基线模板见 `.env.example`。

## 一、先理解一个容易踩的坑：`.env` 被两方消费

同一个 `.env` 文件被两个东西读取，用途不同：

| 消费者 | 时机 | 用途 |
|---|---|---|
| **docker compose** | 执行 compose 命令时 | 做 `${VAR}` 变量插值（端口、密码、模型名传给容器环境） |
| **应用（pydantic-settings）** | 容器启动时 | 读取业务配置（`extra="ignore"`，不认识的就忽略） |

由此产生两条必须记住的规则：

1. **`http://embed:8088` 只在容器网络里有效**。在宿主机上直接 `python -m uvicorn` 跑应用时，
   这个地址解析不了，必须改成 `http://127.0.0.1:8090`（embed 的宿主映射端口）。
2. **改完 `.env` 必须重启相关容器**。compose 的变量插值只在 `up` 时生效：
   ```bash
   docker compose up -d          # 改了端口/环境变量
   docker compose restart api worker   # 只改了应用读的配置，也可用这个
   ```

## 二、数据库

| 变量 | 默认 | 作用 | 改动注意 |
|---|---|---|---|
| `POSTGRES_PASSWORD` | `change_me_pg_pass` | postgres 容器初始化密码 | **只在首次创建数据卷时生效**。数据卷已存在时改这里不会改数据库密码 |
| `DATABASE_URL` | `postgresql://kb:<pwd>@postgres:5432/kb` | 应用连接串 | 必须与上一行密码一致；特殊字符需 URL 编码（`@`→`%40`） |

> **改密码的正确做法**（数据卷已存在时）：
> ```bash
> docker compose exec postgres psql -U kb -d kb -c "ALTER USER kb WITH PASSWORD '新密码';"
> # 然后同步改 .env 的两处，再 docker compose up -d
> ```

## 三、生成模型

| 变量 | 默认 | 作用 |
|---|---|---|
| `LLM_BASE` | `https://apihub.agnes-ai.com/v1` | OpenAI 兼容接口地址，**要带 `/v1`** |
| `LLM_MODEL` | `agnes-3.0-flash` | 模型名，必须与供应商文档一致 |
| `LLM_API_KEY` | 空 | 密钥。为空时 `/api/health` 报 `llm: missing_key`，问答会失败 |

换供应商（DeepSeek / 通义 / 自建 vLLM）只改这三行，代码零改动。
`LLM_API_KEY` 为空不影响入库，只影响问答——这点在排障时有用。

## 四、向量化

| 变量 | 默认 | 作用 | 改动注意 |
|---|---|---|---|
| `EMBED_BASE` | `http://embed:8088/v1` | 向量服务地址 | 云端用 `https://api.siliconflow.cn/v1` |
| `EMBED_MODEL` | `jinaai/jina-embeddings-v3` | 模型名 | **本地服务只支持 fastembed 内置模型**，`BAAI/bge-m3` 已移除 |
| `EMBED_API_KEY` | `local` | 密钥 | 本地服务只校验非空；为空则判定未启用向量 |
| `EMBED_DIM` | `1024` | **向量维度** | ⚠️ 必须与数据库列 `vector(1024)` 一致，见下 |
| `EMBED_REQUIRED` | `true` | 向量失败时的策略 | `true` 整篇失败；`false` 无向量入库（仅关键词可用） |

### `EMBED_REQUIRED` 的两种语义

| 值 | 向量化失败时 | 适用场景 | 代价 |
|---|---|---|---|
| `true` | 文档状态置 `failed`，`error_msg` 写明原因 | **生产默认** | 宁可不可用，也不留不可检索的脏数据 |
| `false` | `embedding=NULL`、`embed_model='none'`，`ext.embed_degraded=true` | 联调、云端欠费期间保可用 | **拒答闸门失效**（无 rerank/余弦分），只有"一条都没召回"才拒答 |

> 结论：`false` 是应急开关，不是长期状态。恢复服务后应改回 `true` 并重新入库。

## 五、重排

| 变量 | 默认 | 作用 |
|---|---|---|
| `RERANK_BASE` | `http://embed:8088/v1` | 重排服务地址 |
| `RERANK_MODEL` | `jinaai/jina-reranker-v2-base-multilingual` | 应用侧声明的模型名 |
| `RERANK_API_KEY` | `local` | 为空则不出重排，`should_refuse` 退回余弦阈值 0.30 |
| `LOCAL_RERANK_MODEL` | 同上 | **embed 容器实际加载**的模型，必须与 `RERANK_MODEL` 一致 |

> 为什么有两个模型名：`RERANK_MODEL` 是应用"以为"调用的名字，`LOCAL_RERANK_MODEL`
> 是服务"真的"加载的名字。两者不一致时不报错但语义混乱，**保持同步**。

## 六、检索参数（调优主战场）

| 变量 | 默认 | 含义 | 调大的效果 | 调小的效果 |
|---|---|---|---|---|
| `TOP_K` | `5` | 最终喂给生成模型的切片数 | 上下文更全，但更长、更慢、更易稀释重点 | 上下文更聚焦，但可能漏关键段落 |
| `CANDIDATES` | `40` | 每路召回的候选数（向量/关键词各取这么多） | 召回更全，重排压力更大 | 更快，但长尾可能召不回 |
| `RRF_K` | `60` | RRF 融合的平滑常数 | 弱化排名差异，两路更平均 | 强化头部排名，更信任单路高分 |
| `NOT_FOUND_THRESHOLD` | `0.35` | **拒答阈值**（作用于重排分） | 更保守，容易误拒答 | 更激进，容易把无关内容当依据 |

### 拒答阈值的实际行为

`should_refuse()` 的判定顺序：

```
无召回            → 拒答
有重排分          → 重排分 < 0.35 则拒答
无重排但有余弦分  → 余弦 < 0.30 则拒答
两者都无          → 不拒答（此时闸门等同关闭）
```

实测参考（当前配置下）：库里有答案的问题 `top_score≈0.76`；无关问题 `top_score≈0.18`。
中间余量够，但**样本只有 2 个**。真实文档上线后必须重标定这个值——见
[07-验收标准](07-验收标准.md#五必须重新标定的参数)。

## 七、存储

| 变量 | 默认 | 作用 | 改动注意 |
|---|---|---|---|
| `STORAGE_DIR` | `/data/files` | 原始文件落盘目录（容器内） | 对应 compose 的 `filedata` 命名卷；改路径要同步改卷挂载 |
| `MAX_UPLOAD_MB` | `200` | 单文件上限 | 超限返回 413；调大要同时确认磁盘余量 |

## 八、服务

| 变量 | 默认 | 作用 | 改动注意 |
|---|---|---|---|
| `APP_PORT` | `9527` | **宿主机**端口 | 容器内固定 8088；改完需 `docker compose up -d` |
| `LOG_LEVEL` | `INFO` | 日志级别 | 排障时临时设 `DEBUG`，**事后改回**，否则日志暴涨 |

## 九、embed 容器专用（compose 层）

| 变量 | 默认 | 作用 |
|---|---|---|
| `EMBED_MODEL` | `jinaai/jina-embeddings-v3` | 容器加载的向量模型 |
| `LOCAL_RERANK_MODEL` | `jinaai/jina-reranker-v2-base-multilingual` | 容器加载的重排模型 |
| `HF_HUB_DISABLE_XET` | `1`（硬编码在 compose） | **必须保持 1**。hf-mirror 的 xet/CAS 协议会返回 401，关掉才走普通 HTTP |

## 十、完整基线（复制即用）

```ini
POSTGRES_PASSWORD=<强密码>
DATABASE_URL=postgresql://kb:<强密码>@postgres:5432/kb

LLM_BASE=https://apihub.agnes-ai.com/v1
LLM_MODEL=agnes-3.0-flash
LLM_API_KEY=<key>

EMBED_BASE=http://embed:8088/v1
EMBED_MODEL=jinaai/jina-embeddings-v3
EMBED_API_KEY=local
EMBED_DIM=1024
EMBED_REQUIRED=true

RERANK_BASE=http://embed:8088/v1
RERANK_MODEL=jinaai/jina-reranker-v2-base-multilingual
RERANK_API_KEY=local
LOCAL_RERANK_MODEL=jinaai/jina-reranker-v2-base-multilingual

TOP_K=5
CANDIDATES=40
RRF_K=60
NOT_FOUND_THRESHOLD=0.35

STORAGE_DIR=/data/files
MAX_UPLOAD_MB=200

APP_PORT=9527
LOG_LEVEL=INFO
```

## 十一、配置改动的影响范围速查

| 改了 | 必须做什么 | 是否需重建镜像 |
|---|---|---|
| `APP_PORT` | `docker compose up -d` | 否 |
| `LLM_*` | `docker compose restart api worker` | 否 |
| `EMBED_BASE` / `EMBED_API_KEY` | `docker compose restart api worker`；存量文档需考虑重跑 | 否 |
| `EMBED_MODEL` / `EMBED_DIM` | **需重建 embed 容器并重新入库全部文档** | 是（模型变） |
| `RERANK_MODEL` | `docker compose up -d embed`（重新加载模型） | 是 |
| `TOP_K` / `RRF_K` / `NOT_FOUND_THRESHOLD` | `docker compose restart api` | 否 |
| `POSTGRES_PASSWORD` | 先改数据库密码，再改 `.env`，再 `up -d` | 否 |
