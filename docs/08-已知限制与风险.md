# 08 · 已知限制与风险

> 面向：所有人，尤其是决策者。
> 写这份文档的目的很直接：**把做不到的事提前说清楚，避免上线后才发现**。
> 隐瞒限制换来的"顺利验收"，最后都会以更大的代价还回来。

## 一、功能限制（明确不支持）

| # | 不支持的事 | 表现 | 有没有计划 |
|---|---|---|---|
| L1 | **扫描件 / 图片型 PDF** | 抽取不到文字 → 切片为空 → 文档 `failed` | P1，需接 OCR |
| L2 | 视频 / 音频入库 | 上传返回 415 | 方案已设计（切段 + 时间戳偏移），代码未实现 |
| L3 | `.docx` / `.xlsx` / `.pptx` | 返回 415 | 未排期，需加解析器 |
| L4 | 网页 / 企业网盘自动同步 | 无此功能，只能手工传 | 未排期 |
| L5 | 多轮对话记忆 | 每次提问独立，不能"接着上一个问题问" | 未排期 |
| L6 | 文档删除 / 覆盖更新 | 无删除接口；改了内容重新上传会**新增一篇**而非替换 | P1 |
| L7 | 用户管理界面 | 只能写 SQL 建用户 | P1 |
| L8 | SSO / 无密码登录 | 需手工填 Bearer Token | P1 |
| L9 | 跨文档推理比对 | 只能各自召回片段，不做"对比 A 和 B" | 未排期 |
| L10 | 表格结构化问答 | 表格会被当纯文本切片，丢失行列关系 | 未排期 |
| L11 | 导出 / 分享答案 | 无此功能 | 未排期 |

## 二、质量限制

| # | 限制 | 说明 | 影响 |
|---|---|---|---|
| Q1 | **评测集只有 8 题** | 验收要求 30 题 | 任何"准确率 xx%"的说法目前都不成立 |
| Q2 | **阈值基于 1 个切片标定** | `0.35` 的样本量是 2（一正一负） | 真实文档上可能误拒答或漏拒答 |
| Q3 | **切片参数未按真实文档调过** | 300–500 字 / 80 重叠是经验值 | 条款很短的制度会切得太碎，很长的会切得超限 |
| Q4 | 答案可能有细微改写 | 生成模型会重组语言 | 数字日期已在提示词里要求逐字照抄，但不保证 100% |
| Q5 | 不处理表格跨页 | 表格被切断 | 跨页表格的问答效果差 |
| Q6 | 中文分词依赖 jieba 词典 | 专有名词可能切错 | 生僻术语检索不到时，可考虑加自定义词典 |

> **核心提醒**：这个系统的定位是"**帮你更快找到原文**"，不是"替你做判断"。
> 引用就是为此存在——**任何要拿去用的结论，都应该点开引用核对一遍**。

## 三、安全相关的已知问题

### 3.1 已实现的安全措施

| 措施 | 状态 |
|---|---|
| 权限过滤写在检索 SQL 的 `WHERE` 里 | ✅ 实现了，**但从未做多部门实测** |
| 文档原文、向量、模型全部本地 | ✅ 只有生成请求出网 |
| `.env` 不入版本库、权限 600 | ✅ |
| 上传大小与格式限制 | ✅ |
| 数据库密码与应用连接串分离 | ✅ |

### 3.2 已知缺口

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| S1 | **权限从未实测** | 🔴 高 | 单用户单部门环境下，越权问题不可能暴露。上线前必须按 [07](07-验收标准.md#三权限验收必测项当前完全未测) 跑 P1–P7 |
| S2 | `GET /api/documents/{doc_id}` 无权限过滤 | 🟡 中 | 知道 UUID 就能看元信息（标题、状态、大小），**不含正文** |
| S3 | `role` 字段无实际作用 | 🟡 中 | 任何登录用户都能上传。若需"只有指定人能传"，要加路由层判断 |
| S4 | `audit_logs` 表存在但从未写入 | 🟡 中 | **没有审计追溯**。谁在什么时候传了什么、问了什么，都查不到 |
| S5 | Token 永久有效、无轮换 | 🟡 中 | 泄露即长期风险，需手工改库 |
| S6 | **发给生成模型的上下文出网** | 🟡 中 | 虽然文档不出内网，但命中的原文片段会发给 Agnes。**涉密文档需评估** |
| S7 | 无 HTTPS | 🟡 中 | 当前明文 HTTP，同网段可嗅探。对外必须套 Nginx + TLS |
| S8 | 无速率限制 | 🟢 低 | 可被刷，但需先有 token |

### 3.3 S6 需要单独说明

这是自建方案最容易被忽略的一点：**"数据不出内网"只成立于检索和存储环节**。

```
文档原文 → 本地解析 → 本地切片 → 本地向量化 → 本地存储   ← 全在网内
                                                    ↓
                              命中的 top5 片段 → 云端生成模型 ← 出网
```

也就是说：**命中的那几段原文，会以明文形式发给生成模型供应商。**

如果文档涉及客户合同、未公开财务数据、个人信息，有三个选择：

1. 换成本地部署的生成模型（如 Ollama + Qwen），代价是质量下降、需要额外机器
2. 只用检索不用生成（`/api/search` 接口已经支持），答案是片段原文
3. 分级管理：敏感的走 `private` 且不参与问答，只做存档

**这件事必须在上线前由业务方拍板，不能默认。**

## 四、架构限制

| # | 限制 | 影响 | 何时需要改 |
|---|---|---|---|
| A1 | 单 worker | 一次只处理一篇文档 | 批量导入几百篇时会很慢 |
| A2 | 队列在 PostgreSQL 里 | 不适合超高并发 | 日入库量 > 1000 篇时考虑独立队列 |
| A3 | 无缓存 | 重复问题每次都重新检索 | 高频问答场景 |
| A4 | 向量维度锁死 1024 | 换模型受限 | 见 [05](05-数据模型与权限.md#四向量维度不可随意更改) |
| A5 | 无水平扩展设计 | api 可多副本，worker 需注意幂等 | 并发上量时 |
| A6 | 迁移无回滚 | 迁移写错只能手工修 | 每次写迁移要谨慎 |
| A7 | 单机部署 | 机器挂了全停 | 需要高可用时 |

## 六、什么情况下**不建议**用这套方案

诚实说，有些场景它不合适：

| 场景 | 为什么不合适 | 建议 |
|---|---|---|
| 文档以扫描件为主（> 50%） | 无 OCR，大半文档进不来 | 先上 OCR，或改用带 OCR 的商业产品 |
| 涉密等级高，内容一个字都不能出网 | 生成环节必须出网 | 换本地大模型，或只用检索不生成 |
| 期望"AI 帮我把制度总结成一份新文件" | 它的定位是问答不是创作 | 用通用 AI 工具（但要人工核对） |
| 文档量 < 20 篇 | 直接 Ctrl+F 更快 | 不必上系统 |
| 只有 1–2 个人偶尔查 | 维护成本高于收益 | 直接用搜索 |
| 需要严格的合规审计追溯 | 无审计日志 | 补 `audit_logs` 写入后再上 |

## 七、当前状态的准确表述

对外介绍时，请用这句：

> **"知识库系统已完成技术验证，在测试数据上跑通了入库、检索、带引用问答、拒答的完整链路；
> 尚未在真实业务文档上做效果验证，权限隔离与备份恢复也还没有实测。
> 下一步是接入真实文档、补评测、做权限验收。"**

不要用：

- ❌ "已上线"（没有）
- ❌ "准确率 95%"（没有依据）
- ❌ "绝对安全，数据不出内网"（生成环节出网）
- ❌ "什么文档都能传"（只支持 pdf/txt/md/csv，且扫描件无效）
